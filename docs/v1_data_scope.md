# V1 数据范围说明

本文档基于以下两份已确认的 Excel 结构检查文档：

- `docs/excel_inspection.md`
- `docs/note_detail_excel_inspection.md`

本文仅定义 V1 的数据范围、统一语义和扩展原则，不包含读取、清洗、数据库或其他业务逻辑的实现。

## 1. V1 目标

V1 的目标是：

- 保存笔记基础信息。
- 保存笔记累计指标快照。
- 保存按天的生命周期数据。
- 支持后续分析曝光、观看、互动、涨粉以及生命周期变化。

V1 暂时不追求导入 Excel 中的全部数据，只纳入当前分析目标所需的字段和时间粒度。

## 2. 第一类 Excel：笔记列表明细表

第一类 Excel 为`笔记列表明细表.xlsx`。V1 使用以下数据。

### 2.1 基础信息

- `笔记标题`
- `首次发布时间`
- `体裁`

### 2.2 累计指标

- `曝光`
- `观看量`
- `封面点击率`
- `点赞`
- `评论`
- `收藏`
- `涨粉`
- `分享`
- `人均观看时长`

### 2.3 暂不使用

- `弹幕`

### 2.4 在 V1 中的职责

这一类 Excel 后续主要负责提供：

- 笔记基础信息。
- 某个导入时间点的累计数据快照。

同一篇笔记在不同导入时间点获得的数据，应按累计指标快照的语义处理，以便后续观察累计指标随导入时间的变化。

## 3. 第二类 Excel：单篇笔记数据明细表

第二类 Excel 为单篇笔记数据明细表。V1 只使用以下按天 Sheet：

- `曝光数（天）`
- `观看数（天）`
- `封面点击率（天）`
- `平均观看时长（天）`
- `涨粉数（天）`

### 3.1 暂不使用

- `平均观看时长（小时）`
- `涨粉数（小时）`
- `基础数据总览`

### 3.2 在 V1 中的职责

这一类 Excel 在 V1 中主要负责提供单篇笔记的每日生命周期数据，用于后续观察笔记各项指标随日期的变化。

已确认的单篇笔记数据明细表内部没有笔记标题、笔记 ID 或笔记链接等身份字段，具体笔记身份由文件名承担。后续读取和关联时需要保留这一事实，但本阶段不实现识别或关联逻辑。

## 4. V1 内部统一数据规则

不同类型 Excel 对相同概念采用了不同的原始表示。V1 在程序内部使用以下统一规则；当前阶段只记录规则，不实现转换代码。

### 4.1 封面点击率

程序内部统一使用 0～1 的小数。

示例：

- 第一类 Excel 中的 `0.201`，内部仍为 `0.201`。
- 第二类 Excel 中的字符串 `"27%"`，后续转换为 `0.27`。

Excel 中的原始表示应在数据清洗阶段转换为上述统一形式。

### 4.2 平均观看时长

程序内部统一使用“秒”为单位的数值。

示例：

- 第一类 Excel 中的 `21`，内部含义为 21 秒。
- 第二类 Excel 中的字符串 `"38s"`，后续转换为数值 `38`。

### 4.3 时间

在后续数据清洗阶段：

- `首次发布时间`转换为 datetime。
- 每日生命周期数据中的`日期`转换为日期或 datetime 类型。

当前阶段只定义转换后的目标语义，不实现转换代码。

## 5. 建议的内部字段名称

以下映射用于统一后续代码和数据库设计中的字段语义，不修改 Excel 原始字段名。

| 内部字段名 | Excel 字段或概念 |
|---|---|
| `title` | 笔记标题 |
| `published_at` | 首次发布时间 |
| `content_type` | 体裁 |
| `impressions` | 曝光 |
| `views` | 观看量 |
| `cover_click_rate` | 封面点击率 |
| `likes` | 点赞 |
| `comments` | 评论 |
| `favorites` | 收藏 |
| `followers_gained` | 涨粉 |
| `shares` | 分享 |
| `avg_watch_time_seconds` | 人均观看时长 |

每日生命周期数据额外包含：

| 内部字段名 | Excel 字段或概念 |
|---|---|
| `date` | 日期 |

第一类和第二类 Excel 的原始名称并不完全一致，例如`曝光`与`曝光数`、`观看量`与`观看数`、`涨粉`与`涨粉数`。后续读取时应通过字段映射归一到上述统一内部语义，但不应改写原始 Excel。

## 6. 可扩展性原则

- V1 不等于最终字段集合。
- 后续可以增加完播率、2 秒退出率、粉丝占比、弹幕或小时级数据。
- Reader 不应依赖固定 Excel 列位置，例如 `A:M`。
- Reader 应优先依据 Sheet 名和字段名读取、校验数据。
- 后续增加指标时，应尽量通过扩展字段映射或数据处理逻辑完成，而不是推翻整个读取模块。
- 当前不要为了未来扩展创建复杂 class、Factory 或其他过度抽象结构。

这里的可扩展性要求只约束后续实现方式，不表示上述扩展字段已进入 V1 范围。V1 实际范围仍以本文第 2、3 节列出的字段和 Sheet 为准。
